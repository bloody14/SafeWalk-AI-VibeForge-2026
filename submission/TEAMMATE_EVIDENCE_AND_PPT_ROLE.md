# Teammate Role — Evidence, PowerPoint and Demo Support (No Coding)

## Operating model

Kundan is the only person coding, using one Antigravity workspace and one ChatGPT CTO conversation. The teammate does not create a separate app, code branch or Antigravity workspace. The teammate's job is to help make the work explainable and submission-ready.

## Before the official start

- Read the project brief and competition rulebook.
- Prepare a blank PowerPoint file or slide outline only; do not insert claims about features not yet built.
- Prepare an evidence folder and this pack's blank logs.
- Keep the organiser's approval for a fresh SafeWalk implementation and prior-prototype disclosure available.

## During the contest

1. Keep a visible timer and remind Kundan of the 20/60/90/100/110-minute gates.
2. Ask Kundan to share actual Antigravity results and browser screenshots.
3. Save genuine screenshots with actual time and short filenames, for example `S01_route-search_10-42.png`.
4. Save the public demo URL and test it on a second browser/device if practical.
5. Record which features are truly working, which use demo data and which use fallback logic.
6. Capture actual Graphify knowledge graph/documentation output if Graphify is used.
7. Build the PPT from actual application screens and verified features.
8. Rehearse the 2-minute demo and divide speaking roles.
9. Ensure the final submission has the source code, project brief, prompt history, demo URL (if available), PPT and disclosures.

## PPT structure (6 slides, maximum)

1. **Title and one-line value proposition** — SafeWalk AI; route awareness for unfamiliar cities.
2. **Problem** — newcomers lack context about lighting, reported incidents, activity and information freshness; explain the user persona.
3. **Solution and user journey** — origin/destination, route comparison, condition factors, AI explanation, completed-route feedback.
4. **Live product** — three to four real screenshots; label DEMO data clearly.
5. **How it works** — map/routing source, deterministic comparison logic, Gemini explanation (only if actually enabled), local feedback persistence and data limitations.
6. **Impact, limitations and next steps** — what the prototype proves, what remains unvalidated, and how trusted city data/community moderation could improve it.

## Do not claim

- A real live crime database if demo data was used.
- Global crowdsourced feedback if only localStorage was implemented.
- A validated safety score or crime prediction.
- Gemini integration if fallback mode was used.
- Public deployment if only localhost worked.

## What to send Kundan/ChatGPT

- Screenshots with actual timestamps.
- Current deployment URL and whether it works.
- The actual Antigravity final report.
- Actual Graphify output/screenshots.
- The real list of completed features and limitations.
- Draft PPT or slide text for review.
